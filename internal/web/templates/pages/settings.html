What this page is

Where this machine keeps things, and how SopsHQ backs itself up. The Paths table shows every folder, file, and address SopsHQ and sops use on this machine, so you never have to guess where they live. The Backups panel controls the encrypted self-backup of this install.

Security note

This page shows paths, names, counts, and status only - never a secret value. The backup password is sealed with the vault and is never displayed.

Keys root folder

The shared keys root (keybase_root) each local OS user with no keystore path of its own derives its key store from, at <root>/<username>/keys.txt. It is machine-local (never replicated) and optional - leave it unset to keep keys under each user's home. Changing it moves no key: it only changes where a key is placed from now on, and keys already placed stay exactly where they are.

Backups

A backup is an encrypted archive of this install - the data directory (your vault-sealed keys, store, oplog, audit), the config, and a plain restore guide - sealed as a whole with AES-256-GCM under a backup password you set. SopsHQ never stores that password in the clear: it keeps only a vault-sealed copy. Save the password in your password manager too - it is required to restore and cannot be recovered from the backup itself.

Audit retention

Keep the audit log from growing without bound. Once a day SopsHQ removes entries older than the number of days you choose. With export then purge it first writes the entries it is about to remove to a timestamped archive file under the data directory's audit-archive folder, then deletes them; with purge it deletes them outright. Set days to 0 to keep the log forever (no automatic removal). This is a per-machine policy, stored in config.jsonc.

Notifications

Send a short message to a Telegram and/or Slack channel when chosen events happen in SopsHQ - applies, drift, failed logins, backups, and more. A notification carries only the event name and outcome (and names/UUIDs), never a secret value. The Telegram bot token and the Slack webhook URL are sealed with the vault and are never shown.

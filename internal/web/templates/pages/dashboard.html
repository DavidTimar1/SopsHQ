Dashboard

About the dashboard & what "Apply" does
What this page is

The dashboard is the control room. The cards count what SopsHQ knows about (keys, projects, machines, OS users, panel logins). The buttons below turn that intended setup into real files on disk.

The buttons
  • Dry run (local) - shows what an Apply WOULD change on this machine, without touching anything. Always safe; use it first.
  • Apply to this machine - places each assigned private key into its OS user's key store and writes every local project's .sops.yaml, then re-encrypts existing secret files to the current public keys. After this, sops -d works locally even if SopsHQ is switched off.
  • Push to all machines - does the same for every registered machine, sending key material to remote machines' agents over the encrypted Tailscale channel. A machine that is not enrolled is skipped and reported.
  • Sync now - pulls the other machines' database changes so both sides agree on the intended setup. This moves records, never secret values.
Before you can Apply

Mark which machine this panel runs on first (Machines -> this machine). Apply needs a key to be generated for an assignment and a folder path for the project on that machine.

Security note

Applying writes PRIVATE keys to disk for the assigned OS users (owner-only permissions). Anyone who can read a placed key can decrypt every secret encrypted to it - so place a key only for users who are meant to decrypt. SopsHQ never auto-unlocks at boot; the vault key is entered by the operator and kept in memory only.

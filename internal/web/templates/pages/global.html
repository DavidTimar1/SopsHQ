Global secrets

About global secrets (define once, share with chosen users)

A global secret set is a named group of values - e.g. OPENROUTER_API_KEY - that is NOT part of a project. You build it by picking one or more per-user keys (each key is owned by one OS user). The set is encrypted to each selected key, so its owner decrypts it with their own key (no shared private key). Pick several keys and each owner gets their own readable copy.

How it works

Each set is written to <key base>/global/<set>/secrets.yaml in every chosen user's own keystore, encrypted to all of them. An app reads it the standard sops way, no SopsHQ in the loop:

  • sops exec-env <path> '<your command>' injects every name=value as an environment variable (the page shows each user's exact path).

A chosen user's private key must be placed for their apps to decrypt - any Apply for one of their projects does this.

Security note

SopsHQ keeps no copy of a value - it encrypts straight into the files and forgets it. Values are hidden until you click Show; a reveal is audited by set + secret NAME only, never the value. Each user reads their own copy with their own key - no key is ever shared between accounts.

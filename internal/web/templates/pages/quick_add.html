Quick add

Add a secret in one guided flow.
  • Pick the secret, choose who should be able to open it and where it is stored, then pick the OS accounts. SopsHQ creates whatever is missing (folder, key pair, secrets file) and encrypts the secret.
  • Remember the two gates: an account can open a secret only if (1) it holds a private key that opens it, and (2) it can read the secrets file on disk.
  • SopsHQ never runs as root. If a step needs system privileges (like creating an OS account), SopsHQ shows you the exact sudo commands to run first.

1. The secret

The value is encrypted immediately; it is never written in plaintext or shown again.

2. Who opens it, and where is it stored?

One secrets file lives in the project's folder. Every OS account you pick gets a copy of the project's private key and can open it. Best when the accounts already share that folder.
Each OS account you pick gets its OWN encrypted copy in its OWN keystore. Best for a service account that should not live in a project folder.

3. Project

Pick a project or create one. A project is a name plus a folder on this machine where its secrets file is written.

3. Secret set

Pick a set or create one. A set is a name that groups global secrets and the OS accounts allowed to open them. Its files are stored under each chosen account's keystore at <keystore>/global/<set>/.

4. Which OS accounts?

  • In a project folder: These accounts each receive a copy of the project's private key. Gate 2 reminder: they must also be able to READ the project folder - SopsHQ warns below if one likely cannot.
  • As a secret set: These accounts are the ones allowed to open the set. Each must already have a key pair (from an earlier setup); SopsHQ blocks and tells you which do not.
